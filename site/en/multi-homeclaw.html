Multi-HomeClaw

Run multiple HomeClaw instances as peers. Cross-instance AI calls via peer_call, remote user messaging, and federated friends.

HomeClaw's multi-instance feature allows you to run multiple HomeClaw Core instances that can communicate with each other as peers. This enables cross-instance AI calls, federated user messaging, and distributed AI systems.

What is Multi-HomeClaw?

Multi-HomeClaw allows you to run multiple HomeClaw Core instances that can communicate with each other as peers. Each instance:

  • Has its own identity — Unique instance ID and display name
  • Runs independently — Different ports, different configurations
  • Can call other instances — AI agents can request help from peers
  • Supports federated messaging — Users can chat across instances

There's no central orchestrator — each instance operates independently and communicates directly with peers via HTTP.

Use Cases

1. Distributed AI Systems

Run specialized instances for different purposes:

  • Coding instance — Optimized for code generation with Cursor/ClaudeCode
  • Research instance — With web browsing and research tools
  • Math instance — Specialized math model for calculations
  • Vision instance — Vision-capable model for image analysis

2. Multi-Location Deployment

Deploy HomeClaw across multiple locations:

  • Home server — Main instance for family use
  • Office server — Work-related tasks and documents
  • Cloud server — Always-on instance for remote access

3. Federated Social Network

Create a distributed social network across instances:

  • Family members — Each family has their own instance
  • Friends — Connect with friends' instances
  • Remote messaging — Chat across instances securely

4. Load Balancing

Distribute work across multiple instances:

  • High availability — Multiple instances for redundancy
  • Resource optimization — Route tasks to most suitable instance
  • Geographic distribution — Serve users from nearest instance

Architecture

Multi-HomeClaw uses a peer-to-peer architecture where each instance:

  1. Has unique identity — Defined in instance_identity.yml
  2. Knows about peers — Listed in peers.yml
  3. Communicates via HTTP — Uses /inbound endpoint for messages
  4. Authenticates securely — API keys for secure communication

Communication Flow

Instance A                    Instance B
    |                              |
    |  POST /inbound               |
    |  (with auth)                 |
    |----------------------------->|
    |                              |
    |  Process request               |
    |                              |
    |  Response                     |
    |<-----------------------------|
    |                              |

Key Components

Component File Purpose
Instance Identity config/instance_identity.yml Defines instance ID, display name, public URL
Peer Roster config/peers.yml Lists known peers and their connection details
Federation Config config/core.yml Enables federation and E2E encryption
User Config config/user.yml Defines users and their remote friends

peer_call Tool

The peer_call tool allows AI agents on one instance to call another instance's AI. This enables distributed AI systems where specialized instances can help each other.

How peer_call Works

  1. Main agent decides — AI on Instance A determines it needs help from a peer
  2. Tool invocation — Calls peer_call with target instance and message
  3. HTTP request — HomeClaw sends POST request to peer's /inbound endpoint
  4. Peer processes — Instance B's AI processes the request
  5. Response returned — Result is sent back to Instance A

peer_call Parameters

Parameter Type Required Description
instance_id string Yes Target instance ID (from peers.yml)
text string Yes Message or task for the peer
user_id string No User ID for the request (default: current user)

Example: Cross-Instance Collaboration

User: "Analyze this code and write tests"

Instance A (General):
"I'll have the coding specialist analyze this."

peer_call(
  instance_id="coding-instance",
  text="Analyze this Python code and write unit tests: [code]"
)

Instance B (Coding Specialist):
"Code analysis complete. Found 3 potential issues.
Here are unit tests: [tests]"

Instance A (General):
"The coding specialist found 3 issues and wrote tests..."

Example: Distributed Research

User: "Research the latest developments in AI"

Instance A (General):
"I'll have the research instance look this up."

peer_call(
  instance_id="research-instance",

Federated User Messaging

Federated messaging allows users on different HomeClaw instances to chat with each other through the Companion app. This creates a distributed social network where each instance maintains its own users and data.

Key Features

  • Cross-instance chat — Users can message users on other instances
  • Federated friendships — Friend relationships span multiple instances
  • Optional E2E encryption — End-to-end encryption for privacy
  • Remote user friends — Add users from other instances as friends

How It Works

  1. User adds remote friend — Adds user from another instance with peer_instance_id
  2. Message sent — Companion app sends message to local Core
  3. Core routes — Local Core forwards to peer instance via /inbound
  4. Peer delivers — Remote Core delivers to target user
  5. Response flows back — Reply follows same path in reverse

Remote Friend Configuration

Add remote friends in config/user.yml:

users:
  - name: Alice
    id: alice
    friends:
      - name: Bob (garage)
        type: user
        user_id: bob
        peer_instance_id: garage-core
      - name: Charlie (office)
        type: user
        user_id: charlie
        peer_instance_id: office-core

End-to-End Encryption

Enable E2E encryption for federated messages:

# In config/core.yml on both instances
federation_enabled: true
federation_e2e_enabled: true
# Optional: require encryption
# federation_e2e_require_encrypted: true

When E2E is enabled:

  • Companion app generates X25519 key pair
  • Public key is registered with Core
  • Messages are encrypted before sending
  • Only recipient can decrypt messages
  • Relaying Cores see only ciphertext

Companion App Experience

In the Companion app:

  • Remote friends — Show cloud/remote badge
  • Chat indicator — Shows "Remote · <instance>"
  • Message prefix — Federated messages may show "◇" prefix
  • Encryption status — Visual indicator for encrypted messages

Setup Guide

Step 1: Configure Instance Identity

Create config/instance_identity.yml on each instance:

# Instance A (home)
instance_id: home-core
display_name: "Home Server"
public_base_url: https://home.example.ts.net:9000
pairing_inbound_user_id: companion_home

# Instance B (garage)
instance_id: garage-core
display_name: "Garage Server"
public_base_url: https://garage.example.ts.net:9000
pairing_inbound_user_id: companion_garage

Step 2: Configure Peers

Create config/peers.yml on each instance:

# On Instance A (home)
peers:
  - instance_id: garage-core
    base_url: https://garage.example.ts.net:9000
    inbound_user_id: companion_garage
    api_key_env: PEER_GARAGE_KEY

# On Instance B (garage)
peers:
  - instance_id: home-core
    base_url: https://home.example.ts.net:9000
    inbound_user_id: companion_home
    api_key_env: PEER_HOME_KEY

Step 3: Enable Federation

Configure federation in config/core.yml:

federation_enabled: true
# Optional E2E encryption
federation_e2e_enabled: true
# Optional: require encryption
# federation_e2e_require_encrypted: true

Step 4: Configure Users

Add users and remote friends in config/user.yml:

users:
  - name: Alice
    id: alice
    im:
      - companion_alice
    friends:
      - name: Bob (garage)
        type: user
        user_id: bob
        peer_instance_id: garage-core

  - name: Bob
    id: bob
    im:
      - companion_bob
    friends:
      - name: Alice (home)
        type: user
        user_id: alice
        peer_instance_id: home-core

Step 5: Set Environment Variables

Set API keys for peer authentication:

# On Instance A
export PEER_GARAGE_KEY="your-secure-key-here"

# On Instance B
export PEER_HOME_KEY="your-secure-key-here"

Step 6: Pair Instances (Optional)

Use CLI commands for automatic pairing:

# On Instance B (recipient)
python -m main peer invite-create 3600

# Copy invite_id, token, and B's URL

# On Instance A (initiator)
python -m main peer invite-accept https://garage:9000   home-core "Home Server"

# Save response and import on both instances
python -m main peer import peer.json PEER_KEY

Step 7: Restart Cores

Restart both instances to apply configuration:

python -m main start

Step 8: Verify Setup

Run doctor to verify configuration:

python -m main doctor

Configuration

Instance Identity Options

Option Type Required Description
instance_id string Yes Unique identifier for this instance
display_name string No Human-readable name for this instance
public_base_url string No* Public URL for HTTPS and pairing
pairing_inbound_user_id string No User ID for inbound pairing requests

*Required when using HTTPS or pairing behind proxies.

Peer Configuration Options

Option Type Required Description
instance_id string Yes Peer's instance ID
base_url string Yes Peer's base URL
inbound_user_id string Yes User ID this peer uses when calling us
api_key_env string No Environment variable name for API key

Federation Options

Option Type Default Description
federation_enabled boolean false Enable federated user messaging
federation_trusted_instances list [] Allowed remote instance IDs
federation_require_accepted_relationship boolean true Require accepted friendship for delivery
federation_e2e_enabled boolean false Enable end-to-end encryption
federation_e2e_require_encrypted boolean false Require encryption for federated messages

Security Settings

# Disable pairing on sensitive instances
peer_pairing_enabled: false

# Rate limiting for pairing
peer_pairing_rate_limit_all: 45
peer_pairing_rate_limit_failed: 18

Companion App Integration

The Companion app seamlessly integrates with multi-instance HomeClaw, allowing users to interact with remote friends and manage multiple instances.

Connecting to Multiple Instances

Users can connect to different instances by:

  • Switching profiles — Different profiles for different instances
  • Multiple accounts — Log in to different instances separately
  • Remote friends — Chat with users on other instances

Remote Friend Management

In the Companion app:

  • Add remote friend — Enter user ID and instance ID
  • View remote status — See which instance friend belongs to
  • Send encrypted messages — E2E encryption when enabled
  • Receive federated messages — Messages from remote instances

Federation Features

  • Automatic key registration — App registers public key with Core
  • Encryption indicators — Visual feedback for encrypted messages
  • Remote badges — Distinguish remote from local friends
  • Instance information — See which instance messages came from

Setup for Users

  1. Configure Core — Set up federation and peers
  2. Add user — Create user account in user.yml
  3. Connect Companion — Set Core URL and API key
  4. Add remote friends — Add users from other instances
  5. Start chatting — Send messages to remote friends

Best Practices

  • Use HTTPS — Always use HTTPS for peer communication
  • Set public_base_url — Configure public URL for proper pairing
  • Enable E2E encryption — Protect federated messages with encryption
  • Use environment variables — Store API keys securely
  • Test with doctor — Run python -m main doctor after changes
  • Monitor logs — Check logs for federation and peer issues
  • Use pairing — Use CLI pairing for easier setup
  • Limit trusted instances — Use federation_trusted_instances for security

Troubleshooting

"Peer not found"

Check that:

  • Peer is listed in config/peers.yml
  • instance_id matches exactly
  • Peer's Core is running

"Authentication failed"

Verify that:

  • API key environment variable is set
  • API key matches on both instances
  • auth_enabled is configured correctly

"Federation disabled"

Ensure that:

  • federation_enabled: true in core.yml
  • Core has been restarted after configuration

"Pairing failed"

Check that:

  • peer_pairing_enabled: true on recipient
  • Invite token is valid and not expired
  • Both instances can reach each other
  • public_base_url is set correctly

"Remote friend not receiving messages"

Verify that:

  • Friend is configured with correct peer_instance_id
  • Target user exists on remote instance
  • Federation is enabled on both instances
  • Network connectivity between instances
