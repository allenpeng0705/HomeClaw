Sub-Agent

Spawn specialized sub-agents for specific tasks using sessions_spawn. Choose models by capability or name for focused work.

HomeClaw's Sub-Agent feature allows you to spawn specialized AI agents for specific tasks. Each sub-agent runs as a separate completion with its own model, enabling you to leverage different capabilities and models for different types of work.

What is Sub-Agent?

A sub-agent is a specialized AI agent spawned by the main HomeClaw agent to handle specific tasks. Unlike the main agent, sub-agents:

  • Run as separate completions — Each sub-agent gets its own LLM call and response
  • Use different models — You can specify which model each sub-agent should use
  • Have no tools — Sub-agents are one-shot workers that return text to the main agent
  • Are stateless — They don't maintain conversation history or memory

The main agent uses the sessions_spawn tool to create and communicate with sub-agents, making it easy to delegate specialized tasks to the most suitable model.

How It Works

When the main agent needs to perform a specialized task, it can call the sessions_spawn tool with specific parameters:

  1. Main agent decides — The main LLM analyzes the task and determines if a sub-agent would help
  2. Tool invocation — Main agent calls sessions_spawn with task details and model selection
  3. Model selection — HomeClaw picks the appropriate model based on capability or explicit name
  4. Sub-agent execution — The selected model processes the task and returns results
  5. Result integration — Main agent receives the sub-agent's output and continues its work

This architecture enables you to use different models for different purposes — a fast local model for simple tasks, a powerful cloud model for complex reasoning, or specialized models for math, vision, or other capabilities.

Model Selection

When spawning a sub-agent, you can specify the model in two ways:

Option 1: Explicit Model Name

Specify the exact model reference from your LLM catalog:

sessions_spawn(
  llm_name="local_models/math_specialist",
  task="Solve this equation: x^2 + 5x + 6 = 0"
)

Option 2: Capability-Based Selection

Let HomeClaw automatically pick a model with the required capability:

sessions_spawn(
  capability="Math",
  task="Calculate the derivative of f(x) = x^3 + 2x^2 + x"
)

HomeClaw will scan your config/llm.yml catalog and select the first available model that has the Math capability tag.

Capability Tags

Capability tags in your LLM catalog help HomeClaw automatically select the right model for each task. Common capabilities include:

Capability Description Example Models
Chat General conversation and reasoning Llama 3, Gemini, GPT-4
Math Mathematical calculations and proofs Mathstral, specialized math models
Coding Code generation and debugging Claude 3.5 Sonnet, GPT-4
Vision Image analysis and understanding LLaVA, GPT-4V
Embedding Vector embeddings for RAG BGE, E5, OpenAI embeddings

Adding Capabilities to Models

Edit your config/llm.yml to add capabilities to your models:

local_models:
  - id: math_specialist
    path: mathstral-7b-Q4_K_M.gguf
    host: 127.0.0.1
    port: 5040
    capabilities: [Math, Coding]
    description: "Specialized for math and coding tasks"

cloud_models:
  - id: GPT-4-Vision
    provider: openai
    model: gpt-4-vision-preview
    capabilities: [Vision, Chat]
    description: "GPT-4 with vision capabilities"

Using sessions_spawn

The sessions_spawn tool is available to the main agent when tools are enabled. Here's how to use it:

Tool Parameters

Parameter Type Required Description
task string Yes The task or prompt for the sub-agent
llm_name string No* Explicit model reference (e.g., local_models/math)
capability string No* Capability tag for automatic model selection
max_tokens integer No Maximum tokens for sub-agent response
temperature float No Sampling temperature (0.0-1.0)

*Either llm_name or capability must be specified.

Example: Math Problem

User: "What's the integral of x^2 from 0 to 3?"

Main Agent: "I'll use a math specialist to solve this."

sessions_spawn(
  capability="Math",
  task="Calculate the definite integral of x^2 from 0 to 3. Show your work."
)

Sub-Agent: "To calculate ∫₀³ x² dx:
1. Find the antiderivative: x³/3
2. Evaluate at bounds: (3³/3) - (0³/3)
3. Simplify: 9 - 0 = 9

The integral equals 9."

Main Agent: "The integral of x² from 0 to 3 is 9."

Example: Code Review

User: "Review this Python function for bugs"

Main Agent: "I'll have a coding specialist review it."

sessions_spawn(
  capability="Coding",
  task="Review this Python code for bugs and suggest improvements: [code]"
)

Sub-Agent: "Found 3 issues:
1. Missing error handling on file operations
2. Variable name shadowing in loop
3. Potential integer overflow in calculation

Suggested fixes: [detailed suggestions]"

Main Agent: "The code review found 3 issues that should be fixed..."

Examples

Use Case 1: Multi-Modal Analysis

Use a vision-capable sub-agent to analyze images while keeping your main model for text:

User: "What's in this image? [uploads screenshot.jpg]"

Main Agent: "I'll use a vision model to analyze the image."

sessions_spawn(
  llm_name="cloud_models/GPT-4-Vision",
  task="Describe what you see in this image: [base64 encoded image]"
)

Sub-Agent: "This is a screenshot showing a code editor with a Python function..."

Main Agent: "The image shows a Python code editor with a function that..."

Use Case 2: Cost Optimization

Use a fast local model for simple tasks and only call expensive cloud models when needed:

User: "What's 2 + 2?"

Main Agent: "Simple calculation, using local model."

sessions_spawn(
  llm_name="local_models/fast_chat",
  task="What is 2 + 2?"
)

Sub-Agent: "4"

Main Agent: "2 + 2 = 4."

Use Case 3: Specialized Knowledge

Use models with specialized training for domain-specific tasks:

User: "Explain quantum entanglement simply"

Main Agent: "I'll use a physics-specialized model for this."

sessions_spawn(
  capability="Physics",
  task="Explain quantum entanglement in simple terms for a beginner"
)

Sub-Agent: "Imagine two coins that are magically connected..."

Main Agent: "Quantum entanglement is like two coins that are magically connected..."

Configuration

Enable sessions_spawn Tool

Make sure tools are enabled in config/core.yml:

tools:
  enabled: true
  # sessions_spawn is automatically available when tools are enabled

Configure LLM Catalog

Set up your models in config/llm.yml with capabilities:

local_models:
  - id: main_chat
    path: llama-3-8b-instruct-Q4_K_M.gguf
    host: 127.0.0.1
    port: 5040
    capabilities: [Chat]
    description: "Main chat model"

  - id: math_specialist
    path: mathstral-7b-Q4_K_M.gguf
    host: 127.0.0.1
    port: 5041
    capabilities: [Math]
    description: "Specialized for math tasks"

  - id: vision_model
    path: llava-1.5-7b-Q4_K_M.gguf
    host: 127.0.0.1
    port: 5042
    capabilities: [Vision]
    mmproj: llava-1.5-7b-mmproj.gguf
    supported_media: [image]
    description: "Vision model for image analysis"

cloud_models:
  - id: GPT-4
    provider: openai
    model: gpt-4-turbo-preview
    capabilities: [Chat, Coding]
    description: "GPT-4 Turbo"

  - id: Claude-3.5-Sonnet
    provider: anthropic
    model: claude-3-5-sonnet-20241022
    capabilities: [Chat, Coding]
    description: "Claude 3.5 Sonnet"

Set Main Model

Configure your main model in config/core.yml:

main_llm: local_models/main_chat
# or
# main_llm: cloud_models/GPT-4

Optional: Tool Selection Model

Use a smaller, faster model for tool selection:

use_tool_selection_llm: true
tool_selection_llm: local_models/fast_chat

Optional: Inject Model Catalog into Prompt

Let the main agent see available models and capabilities:

tools:
  llm_catalog_inject_enabled: true
  llm_catalog_inject_max_chars: 2000

Best Practices

  • Use capabilities for flexibility — Let HomeClaw pick the right model based on task type
  • Explicit names for control — Use llm_name when you need a specific model
  • Balance cost and quality — Use local models for simple tasks, cloud for complex ones
  • Keep tasks focused — Sub-agents work best for well-defined, single-purpose tasks
  • Monitor usage — Check usage reports to see which models are being used most

Troubleshooting

"No model found with capability X"

Check that:

  • You have models with that capability in config/llm.yml
  • The models are marked as available: true
  • The capability spelling matches exactly (case-insensitive)

Sub-agent returns errors

Verify that:

  • The specified model is running and accessible
  • The model file exists at the specified path
  • The host and port are correct

Tools not available

Ensure that:

  • tools.enabled: true in config/core.yml
  • Core has been restarted after configuration changes
