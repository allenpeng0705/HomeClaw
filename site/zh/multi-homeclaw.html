多 HomeClaw

运行多个 HomeClaw 实例作为对等节点。跨实例 AI 调用（peer_call）、远程用户消息和联邦好友。

HomeClaw 的多实例功能允许您运行多个可以相互通信作为对等节点的 HomeClaw Core 实例。这实现了跨实例 AI 调用、联邦用户消息和分布式 AI 系统。

什么是多 HomeClaw？

多 HomeClaw允许您运行多个可以相互通信作为对等节点的 HomeClaw Core 实例。每个实例：

  • 有自己的身份 — 唯一的实例 ID 和显示名称
  • 独立运行 — 不同的端口、不同的配置
  • 可以调用其他实例 — AI 智能体可以请求对等节点的帮助
  • 支持联邦消息 — 用户可以跨实例聊天

没有中心编排器——每个实例独立运行并通过 HTTP 直接与对等节点通信。

用例

1. 分布式 AI 系统

为不同目的运行专用实例：

  • 编程实例 — 优化用于使用 Cursor/ClaudeCode 的代码生成
  • 研究实例 — 带有网页浏览和研究工具
  • 数学实例 — 专用数学模型用于计算
  • 视觉实例 — 具有视觉能力的模型用于图像分析

2. 多位置部署

在多个位置部署 HomeClaw：

  • 家庭服务器 — 家庭使用的主实例
  • 办公室服务器 — 工作相关任务和文档
  • 云服务器 — 用于远程访问的始终在线实例

3. 联邦社交网络

跨实例创建分布式社交网络：

  • 家庭成员 — 每个家庭有自己的实例
  • 朋友 — 与朋友的实例连接
  • 远程消息 — 跨实例安全聊天

4. 负载均衡

在多个实例之间分配工作：

  • 高可用性 — 多个实例用于冗余
  • 资源优化 — 将任务路由到最合适的实例
  • 地理分布 — 从最近的实例为用户服务

架构

多 HomeClaw 使用对等网络架构，其中每个实例：

  1. 具有唯一身份 — 在 instance_identity.yml 中定义
  2. 了解对等节点 — 在 peers.yml 中列出
  3. 通过 HTTP 通信 — 使用 /inbound 端点进行消息传递
  4. 安全认证 — 使用 API 密钥进行安全通信

通信流程

实例 A                    实例 B
    |                              |
    |  POST /inbound               |
    |  (带认证)                   |
    |----------------------------->|
    |                              |
    |  处理请求                   |
    |                              |
    |  响应                         |
    |<-----------------------------|
    |                              |

关键组件

组件 文件 用途
实例身份 config/instance_identity.yml 定义实例 ID、显示名称、公共 URL
对等节点列表 config/peers.yml 列出已知对等节点及其连接详情
联邦配置 config/core.yml 启用联邦和端到端加密
用户配置 config/user.yml 定义用户及其远程好友

peer_call 工具

peer_call 工具允许一个实例上的 AI 智能体调用另一个实例的 AI。这实现了专用实例可以相互帮助的分布式 AI 系统。

peer_call 如何工作

  1. 主智能体决定 — 实例 A 上的 AI 确定需要来自对等节点的帮助
  2. 工具调用 — 调用带有目标实例和消息的 peer_call
  3. HTTP 请求 — HomeClaw 向对等节点的 /inbound 端点发送 POST 请求
  4. 对等节点处理 — 实例 B 的 AI 处理请求
  5. 返回响应 — 结果被发送回实例 A

peer_call 参数

参数 类型 必需 描述
instance_id string 是 目标实例 ID（来自 peers.yml）
text string 是 给对等节点的消息或任务
user_id string 否 请求的用户 ID（默认：当前用户）

示例：跨实例协作

用户: "分析这段代码并编写测试"

实例 A（通用）：
"我将让编程专家来分析它。"

peer_call(
  instance_id="coding-instance",
  text="分析这个 Python 代码并编写单元测试：[code]"
)

实例 B（编程专家）：
"代码分析完成。发现 3 个潜在问题。
以下是单元测试：[tests]"

实例 A（通用）：
"编程专家发现了 3 个问题并编写了测试..."

示例：分布式研究

用户: "研究 AI 的最新发展"

实例 A（通用）：
"我将让研究实例来查找这个。"

peer_call(
  instance_id="research-instance",
  text="研究最新的 AI 发展并总结关键发现"
)

实例 B（研究）：
"最新的 AI 发展包括：
1. GPT-5 公布，推理能力改进
2. 匹配 GPT-4 性能的新开源模型
3. 多模态理解的突破
..."

实例 A（通用）：
"以下是我找到的关于最新 AI 发展的信息..."

联邦用户消息

联邦消息允许不同 HomeClaw 实例上的用户通过伴侣应用相互聊天。这创建了一个分布式社交网络，其中每个实例维护自己的用户和数据。

关键功能

  • 跨实例聊天 — 用户可以与其他实例上的用户消息
  • 联邦好友关系 — 好友关系跨越多个实例
  • 可选端到端加密 — 用于隐私的端到端加密
  • 远程用户好友 — 从其他实例添加用户作为好友

如何工作

  1. 用户添加远程好友 — 添加带有 peer_instance_id 的另一个实例的用户
  2. 发送消息 — 伴侣应用向本地 Core 发送消息
  3. Core 路由 — 本地 Core 通过 /inbound 转发给对等节点
  4. 对等节点投递 — 远程 Core 投递给目标用户
  5. 响应流回 — 回复沿相同路径反向流动

远程好友配置

在 config/user.yml 中添加远程好友：

users:
  - name: Alice
    id: alice
    friends:
      - name: Bob（车库）
        type: user
        user_id: bob
        peer_instance_id: garage-core
      - name: Charlie（办公室）
        type: user
        user_id: charlie
        peer_instance_id: office-core

端到端加密

为联邦消息启用端到端加密：

# 在两个实例的 config/core.yml 中
federation_enabled: true
federation_e2e_enabled: true
# 可选：要求加密
# federation_e2e_require_encrypted: true

启用端到端加密时：

  • 伴侣应用生成 X25519 密钥对
  • 公钥向 Core 注册
  • 消息在发送前加密
  • 只有接收者可以解密消息
  • 中继 Core 仅看到密文

伴侣应用体验

在伴侣应用中：

  • 远程好友 — 显示云/远程徽章
  • 聊天指示器 — 显示 "Remote · <实例>"
  • 消息前缀 — 联邦消息可能显示 "◇" 前缀
  • 加密状态 — 加密消息的视觉指示器

设置指南

步骤 1：配置实例身份

在每个实例上创建 config/instance_identity.yml：

# 实例 A（家庭）
instance_id: home-core
display_name: "家庭服务器"
public_base_url: https://home.example.ts.net:9000
pairing_inbound_user_id: companion_home

# 实例 B（车库）
instance_id: garage-core
display_name: "车库服务器"
public_base_url: https://garage.example.ts.net:9000
pairing_inbound_user_id: companion_garage

步骤 2：配置对等节点

在每个实例上创建 config/peers.yml：

# 在实例 A（家庭）上
peers:
  - instance_id: garage-core
    base_url: https://garage.example.ts.net:9000
    inbound_user_id: companion_garage
    api_key_env: PEER_GARAGE_KEY

# 在实例 B（车库）上
peers:
  - instance_id: home-core
    base_url: https://home.example.ts.net:9000
    inbound_user_id: companion_home
    api_key_env: PEER_HOME_KEY

步骤 3：启用联邦

在 config/core.yml 中配置联邦：

federation_enabled: true
# 可选端到端加密
federation_e2e_enabled: true
# 可选：要求加密
# federation_e2e_require_encrypted: true

步骤 4：配置用户

在 config/user.yml 中添加用户和远程好友：

users:
  - name: Alice
    id: alice
    im:
      - companion_alice
    friends:
      - name: Bob（车库）
        type: user
        user_id: bob
        peer_instance_id: garage-core

  - name: Bob
    id: bob
    im:
      - companion_bob
    friends:
      - name: Alice（家庭）
        type: user
        user_id: alice
        peer_instance_id: home-core

步骤 5：设置环境变量

设置对等节点认证的 API 密钥：

# 在实例 A 上
export PEER_GARAGE_KEY="your-secure-key-here"

# 在实例 B 上
export PEER_HOME_KEY="your-secure-key-here"

步骤 6：配对实例（可选）

使用 CLI 命令进行自动配对：

# 在实例 B（接收者）上
python -m main peer invite-create 3600

# 复制 invite_id、token 和 B 的 URL

# 在实例 A（发起者）上
python -m main peer invite-accept https://garage:9000   home-core "家庭服务器"

# 保存响应并在两个实例上导入
python -m main peer import peer.json PEER_KEY

步骤 7：重启 Core

重启两个实例以应用配置：

python -m main start

步骤 8：验证设置

运行 doctor 以验证配置：

python -m main doctor

配置

实例身份选项

选项 类型 必需 描述
instance_id string 是 此实例的唯一标识符
display_name string 否 此实例的可读名称
public_base_url string 否* 用于 HTTPS 和配对的公共 URL
pairing_inbound_user_id string 否 用于入站配对请求的用户 ID

*使用 HTTPS 或代理后配对时必需。

对等节点配置选项

选项 类型 必需 描述
instance_id string 是 对等节点的实例 ID
base_url string 是 对等节点的基础 URL
inbound_user_id string 是 此对等节点调用我们时使用的用户 ID
api_key_env string 否 API 密钥的环境变量名称

联邦选项

选项 类型 默认值 描述
federation_enabled boolean false 启用联邦用户消息
federation_trusted_instances list [] 允许的远程实例 ID
federation_require_accepted_relationship boolean true 要求接受的好友关系以投递
federation_e2e_enabled boolean false 启用端到端加密
federation_e2e_require_encrypted boolean false 要求联邦消息加密

安全设置

# 在敏感实例上禁用配对
peer_pairing_enabled: false

# 配对速率限制
peer_pairing_rate_limit_all: 45
peer_pairing_rate_limit_failed: 18

伴侣应用集成

伴侣应用无缝集成多实例 HomeClaw，允许用户与远程好友交互并管理多个实例。

连接到多个实例

用户可以通过以下方式连接到不同实例：

  • 切换配置文件 — 不同实例的不同配置文件
  • 多个账户 — 分别登录到不同实例
  • 远程好友 — 与其他实例上的用户聊天

远程好友管理

在伴侣应用中：

  • 添加远程好友 — 输入用户 ID 和实例 ID
  • 查看远程状态 — 查看好友属于哪个实例
  • 发送加密消息 — 启用时端到端加密
  • 接收联邦消息 — 来自远程实例的消息

联邦功能

  • 自动密钥注册 — 应用向 Core 注册公钥
  • 加密指示器 — 加密消息的视觉反馈
  • 远程徽章 — 区分远程和本地好友
  • 实例信息 — 查看消息来自哪个实例

用户设置

  1. 配置 Core — 设置联邦和对等节点
  2. 添加用户 — 在 user.yml 中创建用户账户
  3. 连接伴侣 — 设置 Core URL 和 API 密钥
  4. 添加远程好友 — 从其他实例添加用户
  5. 开始聊天 — 向远程好友发送消息

最佳实践

  • 使用 HTTPS — 始终使用 HTTPS 进行对等节点通信
  • 设置 public_base_url — 配置公共 URL 以正确配对
  • 启用端到端加密 — 使用加密保护联邦消息
  • 使用环境变量 — 安全存储 API 密钥
  • 使用 doctor 测试 — 更改后运行 python -m main doctor
  • 监控日志 — 检查日志以了解联邦和对等节点问题
  • 使用配对 — 使用 CLI 配对以更轻松设置
  • 限制受信任实例 — 使用 federation_trusted_instances 提高安全性

故障排除

"未找到对等节点"

检查：

  • 对等节点在 config/peers.yml 中列出
  • instance_id 完全匹配
  • 对等节点的 Core 正在运行

"认证失败"

验证：

  • 已设置 API 密钥环境变量
  • API 密钥在两个实例上匹配
  • auth_enabled 配置正确

"联邦已禁用"

确保：

  • federation_enabled: true 在 core.yml 中
  • 配置更改后已重启 Core

"配对失败"

检查：

  • 接收者上 peer_pairing_enabled: true
  • 邀请令牌有效且未过期
  • 两个实例可以相互访问
  • public_base_url 设置正确

"远程好友未收到消息"

验证：

  • 好友使用正确的 peer_instance_id 配置
  • 目标用户存在于远程实例上
  • 两个实例上都启用了联邦
  • 实例之间的网络连接
