子智能体

使用 sessions_spawn 生成专用子智能体处理特定任务。按能力或名称选择模型，专注完成工作。

HomeClaw 的子智能体功能允许您为特定任务生成专用 AI 智能体。每个子智能体作为独立的完成过程运行，使用自己的模型，使您能够为不同类型的工作利用不同的能力和模型。

什么是子智能体？

子智能体是由主 HomeClaw 智能体生成的专用 AI 智能体，用于处理特定任务。与主智能体不同，子智能体：

  • 作为独立的完成过程运行 — 每个子智能体获得自己的 LLM 调用和响应
  • 使用不同的模型 — 您可以指定每个子智能体应该使用哪个模型
  • 没有工具 — 子智能体是一次性工作者，将文本返回给主智能体
  • 是无状态的 — 它们不维护对话历史或记忆

主智能体使用 sessions_spawn 工具来创建和与子智能体通信，使将专用任务委托给最合适的模型变得容易。

工作原理

当主智能体需要执行专用任务时，它可以调用带有特定参数的 sessions_spawn 工具：

  1. 主智能体决定 — 主 LLM 分析任务并确定子智能体是否有帮助
  2. 工具调用 — 主智能体使用任务详情和模型选择调用 sessions_spawn
  3. 模型选择 — HomeClaw 根据能力或显式名称选择合适的模型
  4. 子智能体执行 — 选定的模型处理任务并返回结果
  5. 结果集成 — 主智能体接收子智能体的输出并继续其工作

这种架构使您能够为不同目的使用不同的模型——用于简单任务的快速本地模型、用于复杂推理的强大云模型，或用于数学、视觉或其他能力的专用模型。

模型选择

生成子智能体时，您可以通过两种方式指定模型：

选项 1：显式模型名称

从您的 LLM 目录中指定确切的模型引用：

sessions_spawn(
  llm_name="local_models/math_specialist",
  task="解这个方程：x^2 + 5x + 6 = 0"
)

选项 2：基于能力的选择

让 HomeClaw 自动选择具有所需能力的模型：

sessions_spawn(
  capability="Math",
  task="计算 f(x) = x^3 + 2x^2 + x 的导数"
)

HomeClaw 将扫描您的 config/llm.yml 目录并选择第一个具有 Math 能力标签的可用模型。

能力标签

LLM 目录中的能力标签帮助 HomeClaw 自动为每个任务选择合适的模型。常见能力包括：

能力 描述 示例模型
Chat 一般对话和推理 Llama 3、Gemini、GPT-4
Math 数学计算和证明 Mathstral、专用数学模型
Coding 代码生成和调试 Claude 3.5 Sonnet、GPT-4
Vision 图像分析和理解 LLaVA、GPT-4V
Embedding 用于 RAG 的向量嵌入 BGE、E5、OpenAI 嵌入

为模型添加能力

编辑您的 config/llm.yml 为模型添加能力：

local_models:
  - id: math_specialist
    path: mathstral-7b-Q4_K_M.gguf
    host: 127.0.0.1
    port: 5040
    capabilities: [Math, Coding]
    description: "专用于数学和编程任务"

cloud_models:
  - id: GPT-4-Vision
    provider: openai
    model: gpt-4-vision-preview
    capabilities: [Vision, Chat]
    description: "具有视觉能力的 GPT-4"

使用 sessions_spawn

当启用工具时，sessions_spawn 工具对主智能体可用。以下是使用方法：

工具参数

参数 类型 必需 描述
task string 是 子智能体的任务或提示
llm_name string 否* 显式模型引用（例如 local_models/math）
capability string 否* 用于自动模型选择的能力标签
max_tokens integer 否 子智能体响应的最大令牌数
temperature float 否 采样温度（0.0-1.0）

*必须指定 llm_name 或 capability 之一。

示例：数学问题

用户: "x^2 从 0 到 3 的积分是多少？"

主智能体: "我将使用数学专家来解决这个问题。"

sessions_spawn(
  capability="Math",
  task="计算 x^2 从 0 到 3 的定积分。展示你的工作过程。"
)

子智能体: "要计算 ∫₀³ x² dx：
1. 找到原函数：x³/3
2. 在边界处求值：(3³/3) - (0³/3)
3. 简化：9 - 0 = 9

积分等于 9。"

主智能体: "x² 从 0 到 3 的积分是 9。"

示例：代码审查

用户: "审查这个 Python 函数是否有错误"

主智能体: "我将让编程专家来审查它。"

sessions_spawn(
  capability="Coding",
  task="审查这个 Python 代码是否有错误并建议改进：[code]"
)

子智能体: "发现了 3 个问题：
1. 文件操作缺少错误处理
2. 循环中的变量名遮蔽
3. 计算中潜在的整数溢出

建议的修复：[详细建议]"

主智能体: "代码审查发现了 3 个应该修复的问题..."

示例

用例 1：多模态分析

使用具有视觉能力的子智能体来分析图像，同时保持主模型用于文本：

用户: "这张图片里有什么？[上传 screenshot.jpg]"

主智能体: "我将使用视觉模型来分析图像。"

sessions_spawn(
  llm_name="cloud_models/GPT-4-Vision",
  task="描述你在这张图片中看到的内容：[base64 编码的图像]"
)

子智能体: "这是一个显示代码编辑器的截图，其中有一个 Python 函数..."

主智能体: "图片显示了一个带有函数的 Python 代码编辑器..."

用例 2：成本优化

使用快速本地模型处理简单任务，仅在需要时调用昂贵的云模型：

用户: "2 + 2 是多少？"

主智能体: "简单计算，使用本地模型。"

sessions_spawn(
  llm_name="local_models/fast_chat",
  task="2 + 2 是多少？"
)

子智能体: "4"

主智能体: "2 + 2 = 4。"

用例 3：专业知识

使用具有专门训练的模型处理特定领域任务：

用户: "简单解释量子纠缠"

主智能体: "我将使用物理专业模型来解释这个。"

sessions_spawn(
  capability="Physics",
  task="用简单的术语为初学者解释量子纠缠"
)

子智能体: "想象两枚神奇连接的硬币..."

主智能体: "量子纠缠就像两枚神奇连接的硬币..."

配置

启用 sessions_spawn 工具

确保在 config/core.yml 中启用了工具：

tools:
  enabled: true
  # 当启用工具时，sessions_spawn 自动可用

配置 LLM 目录

在 config/llm.yml 中设置带有能力的模型：

local_models:
  - id: main_chat
    path: llama-3-8b-instruct-Q4_K_M.gguf
    host: 127.0.0.1
    port: 5040
    capabilities: [Chat]
    description: "主聊天模型"

  - id: math_specialist
    path: mathstral-7b-Q4_K_M.gguf
    host: 127.0.0.1
    port: 5041
    capabilities: [Math]
    description: "专用于数学任务"

  - id: vision_model
    path: llava-1.5-7b-Q4_K_M.gguf
    host: 127.0.0.1
    port: 5042
    capabilities: [Vision]
    mmproj: llava-1.5-7b-mmproj.gguf
    supported_media: [image]
    description: "用于图像分析的视觉模型"

cloud_models:
  - id: GPT-4
    provider: openai
    model: gpt-4-turbo-preview
    capabilities: [Chat, Coding]
    description: "GPT-4 Turbo"

  - id: Claude-3.5-Sonnet
    provider: anthropic
    model: claude-3-5-sonnet-20241022
    capabilities: [Chat, Coding]
    description: "Claude 3.5 Sonnet"

设置主模型

在 config/core.yml 中配置您的主模型：

main_llm: local_models/main_chat
# 或
# main_llm: cloud_models/GPT-4

可选：工具选择模型

使用更小、更快的模型进行工具选择：

use_tool_selection_llm: true
tool_selection_llm: local_models/fast_chat

可选：将模型目录注入提示

让主智能体看到可用的模型和能力：

tools:
  llm_catalog_inject_enabled: true
  llm_catalog_inject_max_chars: 2000

最佳实践

  • 使用能力以获得灵活性 — 让 HomeClaw 根据任务类型选择合适的模型
  • 显式名称以获得控制 — 当您需要特定模型时使用 llm_name
  • 平衡成本和质量 — 对简单任务使用本地模型，对复杂任务使用云模型
  • 保持任务专注 — 子智能体最适合定义明确的单一用途任务
  • 监控使用情况 — 检查使用报告以查看哪些模型使用最多

故障排除

"未找到具有能力 X 的模型"

检查：

  • 您在 config/llm.yml 中有具有该能力的模型
  • 模型被标记为 available: true
  • 能力拼写完全匹配（不区分大小写）

子智能体返回错误

验证：

  • 指定的模型正在运行且可访问
  • 模型文件存在于指定路径
  • 主机和端口正确

工具不可用

确保：

  • tools.enabled: true 在 config/core.yml 中
  • 配置更改后已重启 Core
